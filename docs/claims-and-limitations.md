# 项目宣称与诚实边界

最后更新：2026-07-10。

本文是 Intel Workbench 对外介绍、实验报告和答辩口径的现行约束。历史设计评审见 `docs/archive/expert-review-brief-2026-07-02.md`，实现状态以根目录 `AGENTS.md` 为准。

## 可以明确宣称

- 系统围绕“多源素材进入专题，形成可复核、可审计报告”构建完整业务闭环，不是单纯聊天界面。
- 回答、矛盾线索和可采纳结论必须绑定服务端校验过的素材引用；引用需命中真实原文片段并通过内容哈希校验。
- 未通过支撑校验的 `support-unverified` 内容只保留在证据台账，不进入最终回答、Finding 或报告。
- 报告具有草稿、提交、核准、导出状态机；`revision + contentHash` 把审批绑定到具体内容，内容漂移会被拒绝。
- 关键操作进入哈希链审计日志，系统可以校验链条是否在当前信任边界内保持连续和自洽。
- OfflineGuard 对应用内已接入的模型和媒体出站调用执行白名单授权与审计；真正的气隙保证仍依赖部署网络。
- 文本模型、ASR、OCR、VLM、Embedding 和 Rerank 均可替换为本地或内网服务；云端服务只是开发期替身。

## 禁止夸大的说法

- 不说“完全防止幻觉”。正确说法是：系统拒绝未接地引用，并阻止未验证内容进入可采纳结论。
- 不说“绝对零外发”。正确说法是：应用层默认拒绝非白名单出站，气隙部署需由网络和运维边界共同保证。
- 不说“审计日志绝对不可篡改”。正确说法是：哈希链可发现链内断裂或不一致；没有外部可信锚时，无法阻止具备文件系统权限的攻击者整体重写整条链。
- 不说“矛盾检测显著优于大模型直出”。2026-07-07 的历史标注集结果为锚定流水线 F1=0.957，直出结果在 0.957–1.000 间波动；2026-07-10 算法增加时间和模态约束后，固定标注集尚待复测。
- 不说“真实涉密系统已经合规认证”。现有角色、密级、审计和审批形成课程演示闭环，但不替代组织级 IAM、密钥管理、外部审计锚和合规测评。

## 当前已知边界

- 矛盾检测为消除跨时间状态误报而收紧候选配对，可能牺牲召回；发布新的质量数字前必须重跑固定标注集。
- 简报概览依赖模型返回结构化 JSON；首次生成失败时只能显示降级统计，没有历史 last-good 概览可回退。
- 未配置真实 Embedding/媒体端点时，相关能力会退化为词面检索、mock 或不可用，不能把管线可运行等同于语义质量可用。
- 扁平文件持久化适合单机、离线和可演示场景；即使已有原子写与串行队列，也不具备数据库级事务、索引和多机协调。
- Runtime 能中止内置工具并隔离迟到结果，但第三方工具若忽略 `AbortSignal`，其已经发生的外部副作用无法撤销。
- 2026-07-10 的 API 真实模型链路已完成；本机 Browser 插件文件缺失，因此同轮未完成浏览器渲染态点击和视觉回归。这是验证环境缺口，不是产品功能结论。

## 对外推荐的一句话

> Intel Workbench 不承诺让模型永不出错，而是把模型输出放进引用校验、人工复核、版本绑定和审计留痕的业务流程，使错误可见、结论可复核、责任可追踪。
