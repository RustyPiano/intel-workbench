# 结论核验与核验池产品流决策

**日期**: 2026-07-03  
**状态**: 已接受  
**适用范围**: 课程演示主线、前端信息架构、报告生成闸门、后续开发上下文

---

## 背景

本项目面向课程老师演示，需要同时体现：

- 创新性：AI 参与素材加工、证据检索、矛盾发现、候选结论生成。
- 工作量：多模态素材、任务流程、问答 agent、结论复核、报告闸门、审计链形成闭环。
- 实用性：关键结论可回溯原始证据，报告不能绕过核验直接生成。
- 应用场景：舆情核查、事件调查、风控研判、情报线索整理、合规调查。

因此系统定位为**多源线索核验工作台**，不是聊天问答系统，也不是单纯报告生成器。

---

## 已接受决策

### 1. 产品定位

最终产品类型选择：**调查核验工作台**。

一句话说明：

> 从多源素材中形成可溯源、可复核、可审计的结论，再基于已核准结论生成报告。

### 2. 主流程

课程演示与产品实现应围绕以下主线：

```text
素材汇入
-> 系统解析
-> 要素 / 时间线
-> 矛盾核验
-> 候选判断进入核验池
-> 必要时补充核验
-> 人工核准
-> 报告生成
-> 复核导出
-> 审计留痕
```

### 3. 问答定位

问答不是主流程入口，也不能直接生成报告。

最终语义：

- `补充核验`：用户追问证据缺口。
- 问答答案必须先进入核验池。
- 进入核验池后仍需人工核准。
- 报告只使用已核准结论。

### 4. 页面与术语

前端页面命名采用：

| 原术语 | 最终术语 | 说明 |
|---|---|---|
| 溯源问答 | 补充核验 | 弱化聊天感，强调证据补洞 |
| 研判结论 / 结论确认 | 结论核验 | 顶部导航与任务阶段名称 |
| 结论池 | 核验池 | 页面内部对象，承载待核验判断 |
| 候选结论 | 待入池候选 | 系统建议，尚未进入核验池 |
| 加入结论池 | 加入核验池 | 候选进入核验池 |
| 转为待复核结论 | 转入核验池 | 问答答案进入核验池 |
| 已核准研判结论 | 已核准结论 | 报告可引用对象 |
| 命题抽取 | 不在前端展示 | 当前没有独立持久化命题池，避免术语露怯 |

页面内部状态采用：

- `待核验`
- `已核准`
- `已驳回`
- `需补证`

### 5. 不可破坏规则

后续开发不得绕过以下规则：

1. 问答答案不能直接进入报告。
2. 候选判断必须先进入核验池。
3. 报告只能引用已核准结论。
4. 结论必须保留支持引用；无支持引用不能入池。
5. 导出前必须保留闸门：未核准结论、无效引用、未处理高危矛盾应阻断导出。
6. 人工核准与导出动作必须进入审计链。

## 演示剧本

面向课程老师的推荐演示路径：

1. 打开专题，第一眼看到系统已发现候选判断、矛盾数量、时间线锚点。
2. 进入 `结论核验`，展示 `核验池` 与 `待入池候选`。
3. 点开一条候选，展示支撑引用能定位原始素材。
4. 对证据缺口进入 `补充核验`，提出一条核验问题。
5. AI 返回带引用答案。
6. 将答案 `转入核验池`。
7. 人工将核验池条目核准。
8. 报告页基于 `已核准结论` 自动生成草稿。
9. 复核导出前展示报告闸门与审计留痕。

## 开发指令

### 前端

优先调整信息架构与文案：

- 顶部导航：`补充核验`、`结论核验`。
- 任务阶段展示：不展示 `命题抽取`，改为 `补充核验取证` 或合并进 `补充核验`。
- `结论核验` 页面主标题：`核验池`。
- `待入池候选` 放在主区域顶部。
- `补充核验` 作为右侧或次级入口，不作为报告入口。
- 报告页文案统一为 `基于已核准结论生成报告`。

### 后端

现有主干可继续使用：

- `Inquiry.claims` 保存带引用问答答案。
- `Finding` 作为核验池条目。
- `Finding.review_status` 作为核准状态。
- `ReportService` 只使用已核准 Findings 生成报告。

建议最小补强：

1. 给 `Finding` 增加来源元数据，例如：

```ts
source?: {
  type: "suggestion" | "inquiry" | "contradiction" | "timeline" | "manual";
  id?: string;
}
```

2. 扩展核验状态时优先复用现有 `draft / approved / rejected`，`需补证` 可先用 `open_questions.length > 0` 或新增状态表达。
3. 强化 `SuggestionService.suggestFindings`，让系统能从矛盾、时间线、要素摘要、材料摘要直接提出更多待入池候选，而不是主要依赖已有问答。

---

## 非目标

- 不做“聊天记录一键生成报告”。
- 不把问答输入框作为首屏主入口。
- 不在前端强调 `命题抽取`，除非后续实现独立持久化命题池。
- 不为了演示绕过报告导出闸门。

---

## 与既有文档关系

本决策收敛 `智能工作流自动化决策文档` 中的体验方向：

- 保留智能引导、候选建议、报告自动草稿。
- 将 “问答到 Finding” 明确改写为 “问答答案转入核验池”。
- 将 “Finding / 研判结论” 在产品层统一解释为 “核验池条目 / 已核准结论”。
