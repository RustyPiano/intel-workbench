# 答辩必答问题

## 1. 这是不是套壳聊天机器人？

不是。聊天只是补充核验入口。系统自己管理专题、素材加工、chunk、引用台账、矛盾候选、Finding 复核、报告状态机、角色密级和哈希链审计；模型是可替换组件，不能绕过这些业务规则。

## 2. 如何防止模型编造引用？

模型不能直接写一个看似合理的来源。`cite` 必须命中服务端实际读取到的 chunk 原文子串，并校验内容哈希和定位信息。未通过支撑判断的内容留在台账，不进入最终回答、Finding 或报告。准确说法是“拒绝未接地引用”，不是“完全防止幻觉”。

## 3. 矛盾检测为什么不直接把所有材料丢给大模型？

系统先分块抽取接地命题，再按实体、属性、模态和时间组织候选，只把可能相关的命题交给判定器。这样每条结果都有两侧出处，也能分批处理大语料。历史小标注集上原始 F1 没有显著胜过直出模型，优势是可溯源、可覆盖和可审计。

## 4. 为什么真实复测最后是 0 条矛盾？

同一船舶在不同时间的速度、航向和状态变化不应互相判成矛盾。加入时间和模态约束后，模拟子集中没有留下满足严格条件的冲突。0 条只是一条 E2E 结果，不是精度证明；新策略可能降低召回，必须重新跑固定标注集。

## 5. 你们如何处理失败？

结构化解析失败会显式标记 degraded/partial；大 JSON 会二分重试；单题自动研判最多重试 3 次；报告渲染失败删除旧产物；简报模型失败保留实时统计和 last-good（若存在）。系统优先暴露失败，不用旧结果或截断前缀冒充成功。

## 6. 审计链是否绝对防篡改？

不是。哈希链能发现链内断裂和不一致，适合完整性校验和追责；若攻击者具有同一文件系统的完全权限且系统没有外部可信锚，他仍可能整体重写日志。真实部署应增加只写存储、远端锚定或硬件信任根。

## 7. “离线”为什么还能用 DeepSeek？

DeepSeek 是开发期真实模型替身，用于验证接口和模型行为。生产目标是把相同的 OpenAI-compatible、ASR、OCR、VLM、Embedding 接口指向本地或内网服务。OfflineGuard 负责应用层白名单授权；真正气隙由部署网络保证。

## 8. 报告审批后被人修改怎么办？

审批绑定 `revision + contentHash`。内容、章节规格或渲染文件漂移后，提交、核准和导出都会拒绝；重新起草会增加 revision 并清空原审批。本轮 E2E 人工修改 markdown 后提交返回 409。

## 9. 为什么不用数据库？

课程项目和离线单机演示优先选择可检查、可复制、可恢复的扁平文件，并补了原子写和串行队列。它不适合多机和大规模并发；规模化时应迁移到 SQLite/Postgres，并保留现有领域状态机和审计契约。

## 10. 当前最需要继续改什么？

第一，用固定标注集复测加入时间/模态后的矛盾召回和 F1；第二，约束简报概览输出，减少首次生成 JSON 失败；第三，在 Browser 环境恢复后补完整的浏览器交互和视觉回归；第四，继续降低全案综合问答延迟。
