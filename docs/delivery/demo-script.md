# Intel Workbench 8–10 分钟演示脚本

## 演示目标

只讲一条主线：多源案卷进入系统后，AI 主动加工和取证，人负责复核，最终得到一份有证据、有审批、有审计的报告。

## 演示前准备

```bash
source dev.env.sh
MINI_AGENT_DEMO=1 pnpm dev:server
pnpm dev:web
```

打开 `http://127.0.0.1:5319`，确认顶栏显示模型、网络和开发模式真实状态。准备三个账号：operator、security、admin。演示时不展示或朗读真实 API key。

## 时间分配

### 0:00–0:50：问题与定位

讲法：

> 情报核验的难点不是让模型写一段话，而是不同材料互相矛盾、结论必须回到原文、报告必须经过复核、越权访问必须留下记录。本项目把模型放进一条可复核的业务流程，不把模型当最终裁判。

### 0:50–2:00：数据与权限

1. 用 operator 登录。
2. 展示专题列表、密级和素材状态。
3. 说明数据以专题为边界，素材、chunk、引用、Finding、报告、审计均有明确状态。
4. 尝试访问高于权限的专题或全局审计，展示服务端拒绝。

讲点：权限不只是隐藏按钮，服务端会返回 403 并记审计。

### 2:00–3:10：上传与自动流水线

1. 新建或打开演示专题。
2. 批量选择素材上传。
3. 展示素材加工状态，以及要素→矛盾→自动研判的自动推进。

讲点：小文件一次批量提交；大文件采用 defer/settle，全部落盘后才启动下游，避免只分析第一份文件。

### 3:10–4:30：研判简报

1. 回到默认首屏“研判简报”。
2. 依次指出时间线、关键实体、矛盾、待核问题、报告覆盖率。
3. 点击一个板块深链到具体证据页面。

讲点：简报不是第二份数据库，而是现有产物的可复核聚合；模型概览失败时会显式降级。

### 4:30–6:10：补充核验与引用台账

1. 提交一个案卷问题或打开已完成问答。
2. 左侧展示 agent 活动流和工具调用。
3. 右侧展示引用台账增长。
4. 点击引用回到原始片段。

讲点：模型必须先检索、读取、登记引用、逐条提交 claim；未通过支撑校验的内容不能进入最终回答和报告。

### 6:10–7:10：矛盾与人工复核

1. 打开矛盾页，展示两侧陈述与出处。
2. 说明系统区分时间、模态和计划/事实，减少把正常状态变化误报为矛盾。
3. 由 security 处置一条矛盾或核准一个 Finding。

讲点：AI 负责提出可复核候选，人负责决定是否采纳。

### 7:10–8:30：报告版本与导出

1. 自动起草报告。
2. 展示覆盖率与缺口。
3. 提交、切换 security 核准、导出。
4. 说明审批绑定 `revision + contentHash`，审批后的内容不能被静默替换。

### 8:30–9:20：审计闭环

1. 打开审计中心。
2. 展示上传、模型出站、复核、拒绝访问、导出等事件。
3. 执行审计链校验。

### 9:20–10:00：诚实总结

> 本项目不声称模型永不出错，也不声称矛盾检测 F1 显著优于直出模型。价值是把不确定输出放进引用校验、人工复核、版本绑定和审计流程。当前仍需复测新矛盾策略的召回率，并进一步稳定简报结构化输出。

## 演示失败时的降级路线

- 模型暂时不可用：使用演示种子数据讲完整复核闭环，并展示界面中的降级状态。
- 媒体服务未启动：只演示文本案卷，不把 mock 结果当真实语义能力。
- 自动研判耗时：展示已完成批次和活动流，不现场等待全部问题。
- 简报概览 JSON 失败：把它作为“失败可见”的证据，继续展示实时统计、覆盖率和报告状态。
