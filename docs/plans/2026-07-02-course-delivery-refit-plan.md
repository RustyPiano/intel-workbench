# 课程交付整改计划：多源线索核验工作台

> 创建：2026-07-02
> 目的：把当前功能较散的 Intel Workbench 收束成可现场演示、可写入实验报告、可回应老师最新要求的课程项目。
> 关键词：真实场景、完整数据管理、完整权限管理、非 AI 套壳、用户友好、可复核闭环。

## 0. 结论

当前项目不是缺少功能，而是功能铺得太开，导致演示主线不清、UI 重点不突出、报告叙事容易被 “AI 平台 / Agent runtime” 稀释。

本轮整改不再继续加大而全能力，改为围绕一个可疑线索专题，打穿一条完整业务闭环：

```
授权用户进入专题
→ 管理多源素材
→ 生成要素 / 矛盾 / 问答结论
→ 点击证据回溯原文
→ 报告提交复核
→ 保密员核准导出
→ 审计记录可查可验
```

最终定位：

> 面向多源线索核验的情报工作台：以专题为单位管理素材，围绕证据溯源、矛盾发现、密级裁剪、报告复核和审计校验形成闭环。

## 1. 老师要求对齐

| 老师要求 | 本项目回应方式 | 现场证据 |
| --- | --- | --- |
| 契合实际的情报工作台 | 以专题为单位管理多源线索，围绕核验、复核、留痕组织流程 | 预置“港口异常活动线索核验”专题 |
| 不能纯 AI 套壳 | LLM 只参与抽取/判定；系统负责素材管理、引用校验、矛盾状态、报告闸门、审计 | 矛盾检测流程、引用 hash 校验、报告导出闸门 |
| 有创新性 | 结构化矛盾检测、证据级溯源、密级权限与审计闭环 | 矛盾页、引用回溯、审计校验 |
| 有工作量 | 前后端、鉴权、文件存储、素材加工、问答、分析、报告、审计、评测 | 代码仓库、测试、演示链路 |
| 完整数据管理 | 专题、素材、加工状态、索引、分析产物、报告、审计均有生命周期 | 专题页、素材页、报告页、审计页 |
| 完整权限管理 | 角色、密级、服务端裁剪、报告复核权限、越权拒绝审计 | operator / security / admin 切换演示 |
| 用户友好 | 工作台主屏围绕“核验任务”重排，减少菜单巡游 | 新工作台 UI 与演示脚本 |

## 2. 设计原则

1. **一条主线，不讲双主线**
   管理能力必须存在，但只作为核验流程中的治理证明穿插展示，不单独做后台巡游。

2. **业务词优先，技术词后置**
   主讲“线索、素材、证据、矛盾、复核、审计”，少讲 RAG、Agent、模型槽、提示词。

3. **真实案例优先，空系统后置**
   现场不从空白项目开始赌模型效果，使用预置专题保证演示稳定。

4. **服务端权限优先，前端隐藏只是辅助**
   权限管理必须能证明 API 层拒绝越权访问，并写入审计。

5. **保守表述安全能力**
   说“离线优先、适合内网受控环境、审计链可提示篡改”，不声称满足真实涉密系统合规认证。

- 固定一套演示专题与样例数据。

- 不把所有功能都塞进现场主流程。

## 4. 目标信息架构

### 4.1 入口

- 登录页：本地账号登录，展示当前系统为受控环境工作台。
- 首页：专题列表、搜索、新建、密级标识、素材数、风险矛盾数、报告状态。
- 总览页：仅作为补充，展示当前权限可见的数据统计。

### 4.2 专题工作台

主屏围绕一个专题的核验状态组织：

- 顶部：专题名称、密级、素材数、矛盾数、报告状态、审计状态。
- 左栏：素材与加工状态。
- 中区：要素、时间线、矛盾线索。
- 右栏：证据详情、问答追问、报告动作。

现有 tab 可以保留，但视觉层需要突出四个核心动作：

- 管素材
- 查矛盾
- 看证据
- 出报告

### 4.3 管理与审计

管理后台只保留演示必要项：

- 用户与角色管理。
- 用户密级设置。
- 账号启停 / 重置口令。
- 审计中心：操作记录、拒绝记录、哈希链校验。

模型状态、提示词配置、能力配置降为附录功能，不进入主演示路径。

## 5. 数据管理设计

### 5.1 数据对象

| 对象 | 作用 | 关键状态 | 需要展示 |
| --- | --- | --- | --- |
| 专题 Case | 数据隔离与研判单位 | active / archived | 名称、密级、负责人、素材数、更新时间 |
| 素材 Material | 原始文件与加工入口 | pending / processing / done / failed | 文件名、模态、大小、加工状态、失败原因 |
| 切块 Chunk | 检索与引用最小单元 | 由素材加工生成 | content_hash、页码/段落/时间码/区域 |
| 要素 Element | 人物、地点、组织、装备、时间、事件 | generated | 名称、类型、频次、出处 |
| 矛盾 Contradiction | 跨素材/素材内冲突线索 | open / resolved / dismissed | 双方陈述、置信度、出处、处理状态 |
| 问答 Inquiry | 专题内追问记录 | answered / insufficient / error | 问题、回答、引用 |
| Finding | 可入报告的研判结论 | draft / approved / rejected | 结论、支持引用、复核状态 |
| 报告 Report | 公文式输出 | draft / in_review / approved / exported | 标题、正文、复核人、导出状态 |
| 审计 AuditEvent | 操作留痕 | ok / deny / error | 用户、动作、对象、结果、hash |
| 用户 User | 权限主体 | enabled / disabled | 角色、密级、是否启用 |

### 5.2 生命周期

专题：

```
创建 → 进行中 → 归档 → 删除
```

素材：

```
上传 → 待加工 → 加工中 → 已加工
              ↘ 失败 → 重试 / 删除
已加工 → 重建索引 → 已加工
```

分析产物：

```
生成 → 绑定来源 → 人工复核 / 处理 → 入报告
```

报告：

```
草稿 → 待复核 → 已复核 → 已导出
      ↘ 修改后回到草稿
```

审计：

```
写入 → 查询 → 校验 → 导出
```

### 5.3 必须落审计的动作

- 登录 / 登出 / 改密
- 创建专题 / 修改专题 / 归档 / 删除
- 上传素材 / 删除素材 / 加工素材 / 重建索引
- 提取要素 / 检测矛盾 / 处理矛盾
- 问答创建 / 引用生成失败
- 创建 Finding / 复核 Finding
- 起草报告 / 提交复核 / 核准 / 导出 / 导出拒绝
- 用户创建 / 启停 / 角色密级修改 / 重置口令
- 越权访问拒绝
- 模型外发授权 / 拒绝

## 6. 权限管理设计

### 6.1 角色

| 角色 | 定位 |
| --- | --- |
| operator | 作业员，负责专题研判、素材管理、问答、提交报告 |
| security | 保密员，负责矛盾处理、报告复核、审计查看 |
| admin | 管理员，负责用户、角色、密级、系统配置 |

### 6.2 权限矩阵

| 操作 | operator | security | admin |
| --- | --- | --- | --- |
| 查看授权专题 | 是 | 是 | 是 |
| 新建专题 | 是 | 可选 | 是 |
| 上传素材 | 是 | 可选 | 是 |
| 删除素材 | 专题负责人可删 | 可选 | 是 |
| 重建索引 / 重新加工 | 是 | 可选 | 是 |
| 运行要素 / 矛盾分析 | 是 | 是 | 是 |
| 智能问答 | 是 | 是 | 是 |
| 创建 Finding | 是 | 是 | 是 |
| 复核 Finding | 否 | 是 | 是 |
| 提交报告 | 是 | 是 | 是 |
| 核准报告 | 否 | 是 | 是 |
| 导出报告 | 报告已核准后可选 | 是 | 是 |
| 查看专题审计 | 否或只读本专题 | 是 | 是 |
| 查看全局审计 | 否 | 是 | 是 |
| 用户管理 | 否 | 否 | 是 |
| 修改角色 / 密级 | 否 | 否 | 是 |

### 6.3 密级规则

密级从低到高：

```
内部 < 秘密 < 机密 < 绝密
```

规则：

- 用户只能读取密级不高于自身 clearance 的专题。
- 专题内素材、分析产物、报告默认继承专题密级。
- 低密级用户请求高密级专题，服务端拒绝或裁剪，不只是在前端隐藏。
- 越权拒绝写入审计，结果为 `deny`。
- 报告导出前必须完成保密员或管理员复核。

## 7. 创新点收束

只主讲三个创新点。

### 7.1 结构化矛盾检测

不是把全文丢给大模型直接问“哪里矛盾”，而是：

```
逐块抽取主张
→ 主张绑定真实 chunk
→ 按实体聚类
→ 簇内成对判断矛盾
→ 输出双方证据与处理状态
```

价值不只在 F1，而在可追踪、可分批、可复核、可审计。

### 7.2 可验证证据溯源

每条结论引用真实素材片段：

- chunk 文本有 `content_hash`
- 引用必须来自系统已加工片段
- 素材变更或 hash 不一致时引用失效
- 用户可点击回到原文、时间码或图像区域

谨慎表述：这是引用真实性校验，不等同于自动证明结论一定正确。

### 7.3 数据、权限、审计、报告复核一体化

普通 AI 问答只给答案；本项目把答案放进业务治理流程：

```
素材管理
→ 分析产物
→ 人工复核
→ 报告闸门
→ 权限控制
→ 审计留痕
```

这是“工作台”区别于“聊天壳子”的核心。

## 8. 演示专题设计

建议固定专题：

> 港口异常活动线索核验（模拟数据）

### 8.1 材料构成

准备 5-8 份材料即可：

- 港口值班简报：某船 22:30 靠泊。
- 监控摘要：同船 23:10 仍在外锚地。
- 通话转写：提到“23 点前完成卸货”。
- 车辆进出记录：22:45 有两辆货车进入 3 号门。
- 图片 OCR：集装箱编号或船名片段。
- 后续情况简报：称“未发现异常卸货”。

### 8.2 必须植入的矛盾

- 时间矛盾：靠泊时间 22:30 vs 23:10 仍在外锚地。
- 数量矛盾：货车 2 辆 vs 4 辆。
- 状态矛盾：已完成卸货 vs 未发现卸货。

### 8.3 预置输出

为稳定演示，提前准备：

- 已加工素材。
- 已抽取要素。
- 已检测矛盾。
- 一条问答历史。
- 一个草稿报告。
- 一条越权拒绝审计。

现场可演示重新运行，但不依赖模型实时成功。

## 9. 现场演示脚本

目标：8-10 分钟。

1. **30 秒：定位**
   - “这是一个多源线索核验工作台，不是聊天机器人。”
   - “核心是把素材、证据、矛盾、权限和审计串成闭环。”

2. **1 分钟：operator 登录**
   - 只看到授权专题。
   - 展示专题密级、素材数、风险矛盾数、报告状态。

3. **1.5 分钟：数据管理**
   - 进入预置专题。
   - 展示素材列表、加工状态、删除/重建索引/重新加工入口。
   - 点开一份材料，看原文或转写。

4. **2 分钟：矛盾核验**
   - 打开矛盾检测页。
   - 只讲一条高质量矛盾。
   - 点击 A/B 双方证据，回到原文片段。

5. **1 分钟：溯源问答**
   - 追问“这条异常的关键证据有哪些？”
   - 展示回答带引用。

6. **1.5 分钟：报告复核**
   - 提交报告。
   - 切 security 账号。
   - 处理矛盾，核准报告。

7. **1.5 分钟：权限与审计**
   - 切 admin 或 security。
   - 展示用户角色与密级。
   - 展示越权拒绝记录。
   - 展示审计链校验。

备用演示：

- 关系网络 / 时间线。
- 全局总览。
- 用户启停 / 重置口令。

不要现场展开：

- runtime 内核。
- 多 agent。
- RAG 变体。
- 模型槽。
- 提示词配置。

## 10. UI 修改计划

### Batch A：演示主线收束

目标：让工作台第一眼就像“核验任务台”。

改动：

- 专题工作台顶部增加核验摘要：素材、已加工、矛盾、待复核、报告状态、审计状态。
- Tab 文案改成更业务化：
  - 素材
  - 要素 / 时间线
  - 矛盾核验
  - 溯源问答
  - 研判结论
  - 报告复核
  - 审计
- 弱化任务阶段条，避免显得流程复杂。
- 在矛盾页突出“证据 A / 证据 B / 处理状态 / 置信度 / 出处”。

验收：

- 老师不需要解释菜单，也能看出主流程。
- 首页和专题页均显示数据管理状态。

### Batch B：数据管理可见化

改动：

- 首页专题卡增加：素材状态、矛盾数、报告状态。
- 素材页统一展示状态、失败原因、重试、重建索引、删除。
- 报告页展示状态机和导出闸门原因。
- 审计页增加按对象/动作过滤。

验收：

- 能演示专题、素材、报告、审计的生命周期。

### Batch C：权限管理可见化

改动：

- 用户管理页增加角色、密级、启停、重置口令。
- 首页展示“当前用户密级下可见专题”。
- 越权失败后审计页能快速定位拒绝记录。

验收：

- operator 与 admin/security 看到的数据不同。
- 越权 API 被服务端拒绝，有审计。

## 11. 后端 / 数据修改计划

优先复用现有服务，少加新模块。

### 必查

- `CaseService`：是否所有专题读取都经过 actor/clearance 校验。
- `MaterialService`：上传、删除、重建索引、加工是否落审计。
- `ReportService`：核准、导出是否按角色限制。
- `AuditService`：deny/error 是否能查询、verify 是否可演示。
- `AdminService` / `UserStore`：用户启停、角色、密级是否可改。

### 可能需要补

- 删除/归档专题入口。
- 用户启停或密级修改 UI。
- 越权访问演示用 API/按钮。
- 审计过滤与导出。
- 演示数据 seed 脚本。

## 12. 实验报告修改计划

   - 业务需求：专题、素材、核验、报告。
   - 数据管理需求。
   - 权限管理需求。
   - 可复核与审计需求。

3. 总体架构
   - Web 作业面 / 管理面。
   - Server 服务层。
   - 文件存储。
   - Agent runtime 作为基础设施，不作为主角。

4. 主要模块实现
   - 专题与素材管理。
   - 多源素材加工。
   - 检索与证据溯源。
   - 要素与矛盾检测。

## 13. 表述边界

避免：

- “AI 情报助手”
- “AI 自动生成情报结论”
- “多 Agent 协同是核心”
- “模型编排平台”
- “完整涉密系统”
- “绝对零外发”
- “完全防篡改”
- “F1 显著优于大模型”

推荐：

- “多源线索核验工作台”
- “辅助核验，提供证据链和复核依据”
- “服务端执行密级裁剪”
- “每条事实性结论可回溯到素材”
- “审计链用于完整性校验和篡改提示”
- “适合内网或受控环境部署，课程演示使用模拟数据”

## 14. 验收标准

### 工程

- `pnpm install` 可完成。
- `pnpm typecheck` 通过。
- 除 Codex 沙箱 TCP 假失败外，测试通过。
- 本地后端和前端可启动。

### 功能

- operator / security / admin 三类账号可登录。
- 不同密级用户看到的专题不同。
- 素材可上传、查看状态、删除或重新加工。
- 矛盾检测页能展示至少一条可复核矛盾。
- 点击证据能回到原文或片段。
- 问答结果带引用。
- 报告必须复核后才能导出。
- 越权拒绝有审计记录。
- 审计链 verify 可演示。

### 演示

- 8-10 分钟内完成主流程。
- 不依赖实时模型生成成功。
- 不展示空白系统。
- 不讲 runtime / 多 agent / 模型槽细节。

### 报告

- 有数据管理和权限管理专章。
- 有权限矩阵和生命周期图。
- 有创新点对比，不写成工具堆砌。
- 有实验数据和诚实边界。

## 15. 执行顺序

1. **基线清理**
   - pnpm workspace 与脚本统一。
   - 确认 typecheck/test 基线。

2. **演示案例**
   - 编写模拟材料。
   - 准备 seed 脚本或 fixtures。
   - 预生成要素、矛盾、报告、审计记录。

3. **权限与数据管理验收**
   - 补权限矩阵对应缺口。
   - 补越权拒绝审计演示。
   - 补素材/专题生命周期缺口。

4. **UI 收束**
   - 首页 / 专题工作台 / 矛盾页 / 报告页 / 审计页。
   - 优先保证演示路径清楚。

5. **报告重写**
   - 按第 12 节结构重写。
   - 截图和图表同步。

6. **最终彩排**
   - 按脚本跑两遍。
   - 记录失败点。
   - 准备备用截图和已加工数据。

## 16. 风险与兜底

| 风险 | 影响 | 兜底 |
| --- | --- | --- |
| 模型响应慢或失败 | 现场中断 | 使用预置已加工数据，实时运行作为备用 |
| 权限逻辑缺口 | 老师追问时失分 | 优先补服务端拒绝与审计，不只改 UI |
| UI 仍像菜单合集 | 观感差 | 首页和专题页改成核验状态台 |
| 报告内容夸大 | 被质疑套壳或虚假能力 | 降低涉密/气隙/防篡改表述 |
| 功能太多超时 | 主线散 | 只演一条矛盾、一条问答、一次复核、一次审计 |

## 17. 完成定义

本轮整改完成的标准不是“功能更多”，而是：

- 老师能在 1 分钟内理解项目用途。
- 现场 8-10 分钟能跑完一条完整核验闭环。
- 数据管理和权限管理有矩阵、有生命周期、有服务端证据。
- 创新点集中在矛盾检测、证据溯源、权限审计。
- 实验报告像技术总结报告，而不是内部整改备忘录。
