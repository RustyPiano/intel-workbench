# 阶段三实施计划：目标驱动的研判工作台

日期：2026-07-06 ｜ 前置：阶段一（成功率）、阶段二（透明化）已合入 main。
执行约定：本文档是阶段三的唯一基准；实现中任何偏离必须记入根目录 `implementation-notes.md` 的 Deviations 节，不得静默改道。

## 0. 目标与不做

**产品主张一句话**：把一份案卷变成一份全覆盖、可审计的核验报告——用户传完文件后系统主动推进，人从"提问者"变成"复核者"。

**解决的三个既有痛点**：
1. 传完文件不知道下一步做什么（流水线是过程驱动、手动推进）；
2. 报告覆盖全靠用户碰巧问了什么问题；
3. 分析动作散落在各 Tab，没有一屏主线。

**不做（Non-goals）**：多 Agent 编排；新报告模板系统（沿用现有 render 管线）；权限模型改动；过程持久化回放与技能激活事件（列为阶段四）；任何"优于大模型直出"式的效果声称。

## 1. 关键决策（最可能需要调整，评审先看这里）

- **D1 研判简报是专题的落地视图**：进入专题默认先看到"研判简报"——案情概览（LLM 生成，绑定引用）、时间线骨架、关键实体、已检出矛盾、待核问题清单、报告覆盖度。现有 TaskOverview 的阶段条并入简报头部，不再是独立的第一屏。每一项深链到对应 Tab。
- **D2 自动化改造现有 9 阶段 task pipeline，不新建系统**：素材加工完成后自动创建/推进 TaskRun，非 checkpoint 阶段（证据单元、补充核验取证、要素抽取、矛盾检测）自动执行对应 job；checkpoint 阶段（实体归并、矛盾检测确认）仍停下等人工。阶段命名从工程词改为用户语言（如"证据单元"→"素材加工"）。实现前先核实 task-service 现有阶段推进与 job 注册的真实接口，以实际代码为准。
- **D3 自动研判批处理复用既有构件**：问题清单由 suggestion 服务（规则+LLM）生成 → 逐题走与 POST /inquiries 相同的 agent 路径 → 产物走既有"问答 claims → Finding 候选池"机制入池。不新建产物类型。默认每案上限 8 题、顺序执行、可中途取消（AbortSignal 贯通）；作为 pipeline 的"补充核验取证"阶段执行体。
- **D4 覆盖率模型**：报告模板固定五节——背景与素材概况 / 关键时间线 / 矛盾核验 / 研判结论 / 未决事项。每节映射证据要求（如"矛盾核验"节要求每条高置信矛盾有处置状态；"结论"节要求 ≥1 条 approved finding）。覆盖度 = 满足要求的节 / 总节数，节内显示缺口明细（"2/4 矛盾未处置"）。在 report-service 计算，简报与报告页共同消费。**覆盖率只做展示与引导，不新增导出硬门禁**（既有引用完整性门禁保持不变）。
- **D5 简报数据模型**：`cases/<id>/brief.json` 缓存（概览段落+统计+生成时间+来源引用），素材/要素/矛盾/结论变更后标记 stale，进入简报时按需重算；LLM 不可用时降级为纯统计简报（无概览段落），页面明示降级。
- **D6 自动模式默认开启但可控**：新建专题默认"上传即自动开跑"；专题设置可关；运行中简报头部有醒目的暂停/停止；所有自动动作写审计（actor 标记为 system-autopilot，密级校验按专题创建者身份收敛——实现时核实现有审计 actor 模型后定，若有冲突记 Deviations）。

## 2. 里程碑与验收

- **M1 自动流水线（server）**：素材 processed 后自动推进 pipeline，非 checkpoint 阶段自动执行要素抽取/矛盾检测 job。
  验收：新建专题→上传→不点任何按钮，要素与矛盾自动就绪，TaskRun 阶段状态正确流转；失败阶段可重试；全量测试通过。
- **M2 研判简报（server+web）**：brief 聚合端点 + brief.json 缓存 + 简报落地视图（D1 版式）。
  验收：进入专题首屏即简报；六个板块数据真实、深链可点；LLM 概览段引用可回溯；降级态可用。
- **M3 自动研判（server+web）**：D3 批处理作为 pipeline 阶段接入，简报"待核问题"实时显示逐题进度（复用阶段二事件流）。
  验收：自动跑完后核验池出现候选结论，简报中问题状态从"待核"变"已产生候选"；可取消；评测脚本 run-agent-eval 改造为复用该批处理路径（顺带解决 --timeout 与答案文本记录两个遗留项）。
- **M4 覆盖率仪表（server+web）**：D4 模型落地，简报+报告页展示覆盖度与缺口。
  验收：缺口提示具体可操作（点击跳转补证据）；补足后覆盖度上升；不影响既有导出门禁行为。
- **M5 收尾**：demo 种子数据适配（演示案卷预置"自动研判已完成"状态）、README/交接文档更新、全量回归 + 一次真模型端到端演练（新建专题→上传→自动跑→简报→报告导出全链路）。

依赖关系：M1 → M3 → M4；M2 与 M1 并行开发、M2 的问题清单/覆盖度板块在 M3/M4 后点亮。

## 4. 风险与回退

- 自动跑增加模型开销与失败面：所有自动阶段失败不阻塞人工路径（Tab 手动操作始终可用），自动化只是"代点按钮"；单阶段失败标记 failed 可重试，不级联。
- LLM 概览段有编造风险：概览每句话绑定引用（复用 cite 校验思路），无引用句不渲染；简报明示"AI 生成，需复核"。
- task pipeline 现有语义不明处（手动 advance 的 UI 依赖、TaskRun 持久化恢复）：M1 先读代码再动手，接口与假设不符时按 Deviations 流程记录并调整方案。

## 5. 演示与叙事联动

阶段三完成后的课堂演示主线变为：登录 → 新建专题上传案卷 → （自动加工与研判实时可见，阶段二透明视图）→ 研判简报一屏读懂案情与矛盾 → 复核候选结论 → 覆盖率驱动补证 → 报告提交/核准/导出 → 审计链校验。每一步都有"人机分工"的讲点，与 refit 计划的"多源线索核验工作台"叙事一致。
