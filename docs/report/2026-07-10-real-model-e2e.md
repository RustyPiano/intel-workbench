日期：2026-07-10  
状态：API 全链路完成；浏览器渲染态验证受本机 Browser 插件缺失阻塞。

## 1. 目的与范围

本次不是质量 benchmark，而是验证修复后的真实运行链路能否在隔离数据目录中完成：

```text
登录 → 新建专题 → 批量上传 → 素材加工 → 矛盾检测
→ 自动研判 → Finding 复核 → 报告起草/提交/核准/导出 → 审计校验
```

文本模型使用 `dev.env.sh` 中配置的真实 OpenAI-compatible 云端替身；测试数据为模拟港口案卷，不含真实敏感信息。没有在文档中记录密钥或会话令牌。

## 4. 矛盾检测实跑与迭代

第一次实跑产生 30 条伪矛盾，主要把同一船舶在不同时间的 AIS 航速、航向和状态变化互相判成冲突。第二次收紧解析后，模型返回的约 20KB JSON 因截断被严格解析器拒绝，结果诚实降级为 0/11，而不是把前缀冒充完整结果。

修复后最终结果：

| 指标 | 结果 |
| --- | ---: |
| 已处理 chunk | 11/11 |
| 接地命题 | 103 |
| 输出矛盾 | 0 |
| warning | 0 |

修复内容：

- 命题显式携带 `entity / attribute / modality / time`；
- 只比较同一实体、属性、模态和归一化时间锚点的命题；
- 计划/预测与已发生事实不互判；
- 大 JSON 解析失败时递归二分批次，单块失败按 partial 暴露。

“0 条矛盾”只说明该模拟子集在当前严格口径下没有输出，不证明算法精度更高。新策略更保守，召回率和 F1 必须另用固定标注集复测。

## 5. 自动研判实跑

早期实跑生成过带“篡改、冒充、未经授权”等未经证据支持的前提问题。修复后要求模型为建议问题同时提交逐字 `evidence_quotes`，并只接受中性开放问题。

最终批次：

- 生成 2 个问题；
- 完成 2/2；
- 两题均产生候选；
- 每题 1 次成功尝试，无残留错误。

其中一题针对船舶时间线，回答依据 23:18、23:27、23:31、23:35、23:37 的连续状态，明确说明这是一段状态演进而非时间线矛盾；另一题指出海关预约单与封志完整性之间仍缺少直接闭环证据。

第一题的一条 `support-unverified` claim 仅留在台账，其余 3 条 supported claim 进入回答，验证了未支撑内容不会进入最终正文。


## 7. 简报降级

真实模型简报概览重算返回不可解析 JSON：

```json
{
  "degraded": true,
  "lastError": "模型未返回可解析的 JSON"
}
```

系统没有把失败伪装成成功，也没有覆盖自动研判 2/2、报告覆盖率 4/5 等实时字段。由于该隔离专题没有更早的成功概览，首次失败时无 last-good 文本可回退；这是仍需改进的模型契约边界。
