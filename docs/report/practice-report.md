# 大模型编程实践报告

**项目名称**：多源线索核验工作台
**演示专题**：港口异常活动线索核验（模拟数据）
**报告日期**：2026-07-02

## 摘要

本项目面向“多源线索核验”场景，交付一个以专题为单位管理素材、证据、矛盾、研判结论、报告复核与审计记录的情报工作台。大模型只用于抽取、问答和辅助判断；系统本身负责数据生命周期、引用校验、密级裁剪、复核闸门和审计链，因此不是单纯的 AI 问答壳。

课程演示围绕一条闭环展开：

```
授权用户登录
→ 查看可见专题
→ 管理多源素材
→ 查看要素 / 矛盾 / 溯源问答
→ 将结论纳入报告
→ 保密员复核并处理矛盾
→ 导出前校验证据和审计
```

## 1. 背景与意义

多源线索核验的难点不在“生成一段回答”，而在于回答之后的治理问题：素材来自不同渠道，结论必须能回到原文，矛盾需要人工处理，报告需要复核，越权访问和导出动作必须留痕。普通聊天式 AI 工具很难证明这些过程。

本项目把模型能力放进业务流程中：素材是权威输入，chunk 与 `content_hash` 是证据单元，Finding 与 Report 是复核对象，AuditEvent 是过程凭证。这样可以向老师展示完整的数据管理和权限管理，而不是只展示提示词效果。

## 2. 需求分析

业务需求：

- 以专题 Case 管理一次核验任务。
- 支持文档、音频、视频、图像等素材进入统一素材池。
- 能展示加工状态、失败原因、重试、重建索引和删除。
- 能生成要素、时间线、矛盾线索和带引用问答。
- 能把已复核结论写入报告，并在导出前执行闸门校验。

数据管理需求：

| 对象 | 关键状态 | 展示重点 |
| --- | --- | --- |
| Case | active / archived | 名称、密级、负责人、素材数、更新时间 |
| Material | pending / processing / done / failed | 文件名、模态、大小、加工状态、失败原因 |
| Chunk | 由素材加工生成 | `content_hash`、段落/页码/时间码/区域 |
| Element | generated | 名称、类型、频次、出处 |
| Contradiction | open / resolved / dismissed | 双方陈述、置信度、出处、处理状态 |
| Inquiry | answered / insufficient / error | 问题、回答、引用 |
| Finding | draft / approved / rejected | 结论、支持引用、复核状态 |
| Report | draft / in_review / approved / exported | 标题、正文、复核人、导出状态 |
| AuditEvent | ok / deny / error | 用户、动作、对象、结果、hash |
| User | enabled / disabled | 角色、密级、是否启用 |

权限需求：

| 操作 | operator | security | admin |
| --- | --- | --- | --- |
| 查看授权专题 | 是 | 是 | 是 |
| 上传 / 删除素材 | 是 | 可选 | 是 |
| 运行要素 / 矛盾分析 | 是 | 是 | 是 |
| 创建 Finding | 专题负责人 | 是 | 是 |
| 复核 Finding | 否 | 是 | 是 |
| 提交报告 | 是 | 是 | 是 |
| 核准报告 | 否 | 是 | 是 |
| 查看全局审计 | 否 | 是 | 是 |
| 用户管理 | 否 | 否 | 是 |

密级规则为：内部 < 秘密 < 机密 < 绝密。用户只能读取不高于自身 clearance 的专题；低密级请求高密级专题时，服务端拒绝并写入 `deny` 审计。

## 3. 总体架构

```
React Web 作业面 / 管理面
        │ Bearer 会话令牌
Express Server
        ├─ Auth / UserStore：本地账号、scrypt 口令、角色和密级
        ├─ CaseService / MaterialService：专题与素材生命周期
        ├─ Inquiry / Elements / Contradictions：模型辅助分析，输出带引用
        ├─ Finding / Report：人工复核与导出闸门
        └─ AuditService：append-only 哈希链审计
        │
文件存储：cases/<id>/、audit/audit.jsonl、config/users.json
```

`mini-agent` runtime 是基础设施，用于受控问答与工具调用；课程主讲点不是 runtime 平台，而是工作台如何把模型输出纳入证据、权限、报告和审计闭环。

## 4. 主要模块实现

专题与素材管理：`CaseService` 扫描 `cases/<id>/manifest.json` 生成专题列表；`MaterialService` 负责上传、加工、删除、重建索引，并把关键动作写入审计。

证据溯源：素材加工后生成 chunk，每个 chunk 记录 `content_hash` 和定位信息。引用通过 `chunkToCitation` / `validateCitationIntegrity` 绑定真实片段；素材变更或 hash 不一致时，报告导出闸门会拒绝。

矛盾核验：系统不是把全文直接问“哪里矛盾”，而是按“抽取主张 → 绑定 chunk → 按实体聚类 → 簇内成对判断 → 输出双方证据”的流程组织结果。矛盾状态可由保密员或管理员标记为 resolved / dismissed。

报告复核：报告状态机为 `draft → in_review → approved → exported`。未复核报告不能导出；即使已复核，导出前仍会检查引用、Finding 状态和高置信未处理矛盾。

权限与审计：所有受保护 API 都从服务端会话解析身份。专题读取按 clearance 裁剪；越权访问会写入 `case.access deny`。审计日志包含 `payload_hash / prev_hash / event_hash`，可通过审计中心 verify。

## 5. 创新点

1. **结构化矛盾检测**：把冲突判断拆成可追踪的结构化流程，每条矛盾都有 A/B 双方证据、出处和处理状态。
2. **可验证证据溯源**：事实性结论引用真实 chunk，引用携带内容 hash 与定位，不依赖模型自称“有依据”。
3. **权限 / 审计 / 报告闸门一体化**：答案不是终点，必须经过 Finding、报告复核、导出闸门和审计留痕。

## 6. 实验与效果

检索实验使用合成情报语料评估 BM25、dense、rerank 与查询增强。结论是：强 baseline 在清洁语料上已接近饱和，Contextual Retrieval 只带来小幅重排收益，query rewrite / HyDE 在该基准上没有稳定提升。因此系统默认保守开启基础检索，增强能力作为可选项。

矛盾检测实验使用带标注的模拟案卷，比较结构化 anchored 流水线与大模型直出。当前结果是 F1 持平，而结构化方案额外提供逐条 provenance、覆盖范围、可复核状态和审计记录。报告中不夸大为“模型效果显著优于大模型直出”，只强调其治理价值。

## 7. 演示数据

预置专题：`港口异常活动线索核验（模拟数据）`。

材料包括：

- 港口值班简报：22:30 蓝海星号已完成靠泊。
- 监控摘要：23:10 蓝海星号仍在外锚地。
- 通话转写：提到 23 点前完成卸货。
- 车辆进出记录：22:45 两辆货车进入三号门。
- 堆场清点记录：共有四辆货车进入三号门。
- 后续情况简报：未发现异常卸货。

植入矛盾：

- 靠泊时间 / 位置矛盾：22:30 已靠泊 vs 23:10 仍在外锚地。
- 数量矛盾：两辆货车 vs 四辆货车。
- 状态矛盾：23 点前完成卸货 vs 未发现异常卸货。

## 8. 演示脚本

1. operator 登录，首页只显示当前密级可见专题。
2. 进入港口异常活动专题，查看素材加工状态。
3. 打开矛盾核验，展示 A/B 证据和出处。
4. 打开溯源问答，展示回答携带引用。
5. 查看报告复核，说明未复核和未处理高置信矛盾会阻止导出。
6. 切换 security，处理矛盾并核准报告。
7. 打开审计中心，过滤 `deny`，展示越权拒绝记录和哈希链校验。
8. 切换 admin，展示用户角色、密级、启停和重置口令。

## 9. 不足与边界

- 演示数据为模拟材料，不代表真实业务数据。
- 模型效果依赖本地或内网模型配置；演示不依赖实时模型成功。
- 审计链用于完整性校验和篡改提示，不等同于真实涉密系统合规认证。
- 当前权限模型满足课程演示闭环，真实部署还需要组织、岗位、审批流和外部审计锚定。
