## 摘要

本项目实现了一个面向受控/离线环境的**多源线索核验工作台**（Intel Workbench）。系统把文档、音频、图像、视频等多模态素材汇入同一专题后，自动完成加工、检索、矛盾检测、研判取证与报告复核，并将模型输出**约束在可复核的证据链内**：每一条回答、每一处矛盾、报告的每一节都绑定到素材原文片段、定位信息与内容哈希，关键操作写入哈希链审计日志。系统底层基于自研的 Agent Runtime（自建 agent 循环、工具系统、流式输出、可恢复会话与运行轨迹），产品层不要求分析员直接操作底层模型。

与"让大模型直接回答"的做法相比，本系统的定位不是追求更高的原始精度，而是用**结构化、可溯源、可审计、人机分工**的工程手段，把 LLM 从"不可信的黑箱"改造成"可复核的取证助手"。2026-07-07 的历史标注集上，结构化矛盾检测 F1=0.957，大模型直出在 0.957–1.000 间波动；2026-07-10 算法增加时间与模态约束后尚待重跑固定标注集，因此本文不宣称精度优势。检索在清洁合成语料上 R@10=0.95。当前仓库约 3.25 万行 TypeScript 源码、2.31 万行测试和 0.12 万行评测脚本，927 个测试通过、3 个按外部模型条件跳过。

## 一、研究背景与意义

**背景。** 在情报研判、安全审查、案件核验等场景中，分析员面对的是**多来源、易矛盾、需追责**的材料：同一事实在不同素材里说法不一，结论一旦写入报告即需对每句话负责。近年大语言模型（LLM）在阅读理解与信息抽取上能力很强，但直接把材料丢给 LLM 让它"给个结论"存在三个致命问题：

1. **幻觉与不可溯源**：模型可能编造材料里不存在的细节，且无法逐句回指到证据。
2. **不可审计**：一次性黑箱推理，事后无法复现"结论是怎么来的、看了哪些材料"。
3. **不符合受控环境约束**：涉密/内网场景要求数据不外发、模型可离线部署、操作留痕。

**意义。** 本项目探索的核心问题是：**在不假设模型绝对可靠的前提下，如何用工程手段让 AI 辅助研判变得可信、可复核、可交付？** 这不是一个"再训练一个更强模型"的问题，而是一个**系统与流程设计**的问题——通过强制引用接地、结构化管线、哈希链审计、密级与零外发治理，把不确定的模型输出收敛进一条可以被人复核和追责的证据链。这一思路对任何"高可靠性要求下使用 LLM"的实际场景都有借鉴价值。

**四条硬性设计红线**（贯穿全系统）：

- **应用层默认拒绝外发**：应用内已接入的出站调用统一经 OfflineGuard 白名单审计；真正的气隙保证仍由部署网络提供。模型走 OpenAI-compatible 接口，可指向本地/内网服务。
- **结论必有引用**：任何可采纳结论必须绑定素材原文的逐字引用与内容哈希，无支撑时系统如实回"材料不足"，不臆造。
- **审计可校验**：关键操作写入 SHA-256 哈希链，可验证链内连续性和自洽性；没有外部可信锚时不声称绝对不可篡改。
- **未复核不导出**：报告须走草稿→提交→核准→导出状态机，引用完整性不达标不得导出。

## 二、总体架构与主要功能

### 2.1 总体架构

系统是一个 pnpm monorepo，分三层：

```
┌─────────────────────────────────────────────────────────────┐
│  packages/web  ——  React 工作台（作业面 / 管理面）            │
│  研判简报 · 素材 · 要素图 · 矛盾核验 · 补充核验(活动流+证据台账) │
│  · 结论核验 · 报告 · 审计中心                                  │
└───────────────────────────┬─────────────────────────────────┘
                            │ REST / SSE（会话令牌鉴权）
┌───────────────────────────┴─────────────────────────────────┐
│  packages/server  ——  Intel Workbench API                     │
│  鉴权 · 专题 · 素材加工 · 混合检索 · 证据级问答 · 矛盾检测 ·   │
│  要素/时间线 · 研判简报 · 自动流水线 · 报告 · 哈希链审计 ·     │
│  密级 · OfflineGuard 零外发守卫                                │
│  持久化：扁平文件（cases/<id>/…，原子写 + 单写者队列）         │
└───────────────────────────┬─────────────────────────────────┘
                            │ 深度集成（自定义工具 + 中间件 + 守卫适配器）
┌───────────────────────────┴─────────────────────────────────┐
│  packages/core  ——  自研 Agent Runtime（npm 名 mini-agent）   │
│  agent 循环 · 工具系统(zod 校验) · 流式 · 可恢复 JSONL 会话 ·  │
│  运行轨迹(run trace) · 技能(skills) · OpenAI-compatible 适配器 ·│
│  策略/沙箱(readOnly、路径限制、敏感路径拒绝)                    │
└─────────────────────────────────────────────────────────────┘
             ↕ 模型服务（文本 OpenAI-compatible；媒体 ASR/OCR/VLM/Embedding/Rerank 槽位）
```

**关键设计**：server 在问答与矛盾检测两处**深度驱动** core 的 agent 循环，但**替换掉** core 内置的读写/bash 工具，改注入一套**只读、强制引用**的领域工具，配合审计中间件与"守卫适配器"（出站前必过 OfflineGuard 授权，否则默认失败关闭）。这样既复用了运行时的成熟能力（流式、可恢复、轨迹），又把 agent 的行动收进了"只读素材、强制溯源、零外发"的笼子里。

### 2.2 主要功能（一条业务主线）

系统围绕**"把一份案卷变成一份全覆盖、可审计的核验报告"**组织，用户的心智负担被降到最低：

```
新建专题 → 上传多模态素材 → 系统自动加工与研判（要素→矛盾→自动研判）
   → 进入即见「研判简报」一屏读懂案情、时间线、矛盾、待核问题、报告覆盖度
   → 人工复核候选结论 / 处置矛盾（覆盖率仪表引导补证）
   → 报告草稿 → 提交 → 核准 → 导出 → 审计链校验
```

其中"系统自动研判"是本项目后期的重点：素材加工完成后自动推进核验流水线，并由 AI 主动出题、逐题取证、把候选结论送入核验池——**分析员的角色从"提问者"变为"复核者"**。

## 三、主要模块与技术实现

### 3.1 自研 Agent Runtime（packages/core）

不依赖第三方 agent 框架，自建一套确定性的运行时：

- **agent 循环**：构建系统提示 → 调模型 → 记录 → 顺序执行工具 → 回填结果 → 循环，直至无工具调用或达 maxTurns。工具结果做**字节稳定序列化**，保证实时运行与会话恢复逐字节一致。
- **工具系统**：每个工具用 zod 定义参数 schema，统一超时、中止、错误归一化；支持注入领域工具。
- **流式与可恢复**：端到端 SSE 流式（逐 token + 工具事件）；会话以 JSONL 落盘，可按 session-id 恢复并修复悬空工具调用。conversation-local 技能状态、工具 artifact 和 repair 记录可恢复；同一 session 的进程内与跨进程写入通过锁串行化。
- **模型适配器**：OpenAI-compatible 适配器实现 `generate` 与 `stream` 两条路径（含 DeepSeek 风格思维链 `reasoning_content` 透传），并支持可配置的输出上限 `MINI_AGENT_MAX_OUTPUT_TOKENS`。
- **策略/沙箱**：只读模式、工作区路径限制、敏感路径（`~/.ssh`、`docker.sock` 等）拒绝、有界输出、密文冗余脱敏。

### 3.2 多模态素材加工与混合检索

- **加工**：文档经本地解析→归一化→切块（目标 600 字符、上限 1200）；音/视频/图像走媒体管线（ASR/关键帧/OCR/画面描述），产出统一的文本块与定位信息。
- **检索**（`inquiry/retrieval.ts`）：**BM25 全文**（含 CJK 二元+一元分词）与**稠密向量**（自定义二进制 `.vec` 格式、余弦检索）经**倒数排名融合（RRF）**合并，可选**重排（rerank）**二阶段；并实现了 Anthropic 式**上下文检索**（为每个切块生成上下文前缀再索引）。按 token 预算在"全量上下文"与"检索召回"间路由。
- **诚实说明**：稠密检索需配置真实 embedding 端点；未配置时降级为哈希 mock（无语义），仅验证管线打通。

### 3.3 证据级问答：引用台账 agentic RAG（本项目最核心的机制）

问答不是"检索→拼 prompt→让模型答"，而是一个**带引用台账（citation ledger）的 agent 取证循环**（`inquiry/inquiry-service.ts` + `intel-harness.ts`）：

- agent 只拥有一组**只读领域工具**：`search_chunks`/`search_materials`/`read_material_window`/`expand_chunk`/`read_chunk`/`cite`/`add_claim`/`submit_finding`/`finalize_answer`，以及按需的媒体工具（转写/画面描述/OCR）。
- **引用接地是硬约束**：`cite` 工具拒绝任何非原文逐字子串、或内容哈希不匹配的引用；最终答案**只能由已登记引用构成**；另有 LLM 支撑判定为每条引用标注"支持/提及/矛盾"。若无任何可接地结论，系统如实回"现有材料不足以判断"，而非编造。
- **读取预算**：每次问答有读取字节预算与单次上限，防止无节制读全库。

### 3.4 结构化矛盾检测（原创 skill）

一个两阶段的、类 NLI 的确定性管线（`analysis/contradiction-service.ts`）：

1. **抽取**：分批让 LLM 从切块抽取原子主张 `{entity, attribute, value, modality, time, chunk_id}`，每条主张**接地回真实引用**（哈希校验），伪造锚点直接丢弃；大 JSON 不可解析时递归二分批次，单块失败显式标记 partial；
2. **聚类与判定**：按归一化实体、属性、模态和时间锚点组织候选，计划/预测与已发生事实分开，避免把同一对象不同时间的正常状态变化误报为矛盾；仅在同簇内成对判断；
3. **产出**：每条矛盾绑定 A/B 两侧引用、置信度、scope（跨素材/素材内），全程可回溯。

### 3.5 研判简报与目标驱动自动流水线

- **自动流水线**（`task/autopilot-service.ts`）：素材全部加工完成后，自动创建核验任务并预跑要素抽取→矛盾检测→自动研判；checkpoint 阶段（实体归并、矛盾确认）仍停下等人工。可按专题开关，全程以 `system-autopilot` 身份写审计。
- **自动研判批处理**（`inquiry/auto-inquiry-service.ts`）：由建议引擎（规则+LLM）出题，逐题走**与手动完全相同**的 agent 问答路径，把候选结论送入核验池，进度落盘供简报轮询。
- **研判简报**（`brief/brief-service.ts`）：专题默认首屏，聚合案情概览（LLM 生成，**逐句校验引用**，不过关的句子直接丢弃）、时间线骨架、关键实体、未处置矛盾、待核问题、报告覆盖度，各板块深链到对应页面；结果带指纹缓存，模型不可用时降级为纯统计简报。

### 3.6 报告、覆盖率、审计、密级与零外发治理

- **报告**：草稿→提交→核准→导出状态机；`revision + contentHash` 把提交、审批和导出绑定到具体章节规格与 markdown 内容，任何漂移都需重新起草/审批；导出前还有引用完整性与未处置高置信矛盾门禁。
- **覆盖率仪表**（`report/coverage.ts`）：固定五节模板（背景/时间线/矛盾核验/结论/未决事项），每节映射证据要求，展示覆盖度与缺口明细并深链补证——**只引导不新增硬门禁**。
- **哈希链审计**（`audit/audit-service.ts`）：每条审计事件记 `payload_hash / prev_hash / event_hash`，追加式、单写者，可独立 `/verify` 校验完整性。
- **密级**：四级（内部<秘密<机密<绝密），按用户密级做读权限校验。
- **OfflineGuard**：应用层出站白名单，每次授权/拒绝均审计；守卫适配器包裹模型适配器，出站前必授权，默认失败关闭。

### 3.7 研判过程透明化（让 AI 的行动"看得见"）

把 agent 的运行过程做成**活动流 + 证据台账**双栏界面（类 Claude Code 的体验）：左栏按事件顺序展示叙述、**思考过程**、**工具调用卡**（人话标题、参数摘要、结果摘要、可展开明细）；右栏实时展示**引用台账的生长**、读取预算与候选结论。为此设计了**事件协议 v2**（11 种 SSE 事件 + 13 个工具的本地化摘要器 + 思维链透传）。过程与结论一样可追溯，直接支撑"不臆造、可复核"的产品主张。

## 四、评测与实验结果

本项目坚持**"先测量、后修复、再复测"**，并敢于报告阴性结果——这些数据既是工程依据，也是本报告最有价值的部分之一。

### 4.1 检索质量（RAG）

在自建合成语料上，混合检索（BM25 ⊕ 稠密，RRF 融合）+ 重排的基线 **R@10 ≈ 0.95**，已接近饱和。进一步实现的三种增强（上下文检索、查询改写、HyDE）**均无净增益，HyDE 反而拉低指标**——因此三者默认关闭。结论：这些增强**定义了适用边界**，而非"越多越好"。

### 4.2 结构化矛盾检测（2026-07-07 历史基线）

语料：自建带标注案卷（≈30 切块 / 6 虚构文件 / 12 条金标矛盾对）。

| 方案 | Precision | Recall | F1 |
| --- | ---: | ---: | ---: |
| 锚定流水线（NLI 关思考，默认） | 1.000 | 0.917 | **0.957** |
| 锚定流水线（NLI 开思考） | 1.000 | 0.833 | 0.909 |
| 大模型直出（全块丢 LLM 列矛盾） | 1.000 | 1.000 | 1.000（本次） |

**诚实结论**：这是 2026-07-07、时间/模态约束加入前的历史结果。锚定流水线 F1 与大模型直出持平或略低，结构化价值在逐条可校验引用、分批覆盖和审计，而非原始 F1。2026-07-10 新策略为减少跨时间误报收紧了候选配对，可能牺牲召回；在固定标注集复测前，旧数字不能称为“当前代码结果”。

### 4.3 思维分流消融（数据驱动的反直觉结论）

在 2026-07-07 历史基线上，NLI 开思考 F1=0.909（recall 0.833），低于关思考 F1=0.957（recall 0.917）。因此当时按数据把 NLI 默认路由到关思考。该消融仍说明“更长推理不必然更好”，但随当前候选生成策略一起重跑后才能形成新的发布口径。

### 4.4 问答成功率的工程修复（可复现的前后对比）

用固定 10 题问题集在真实模型端点评测（`pnpm eval:agent`）：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 错误率 | 30%（全部为 `finalize_answer` 参数解析失败） | **0%** |
| 成功作答 | 60% | **80%** |
| 超时（评测器 180s 上限） | 0% | 20%（两道全案综合题） |

**根因诊断**：最终结论一次性打包成大 JSON，被模型默认 4096 token 上限截断，且运行时对解析失败直接判死。**修复**：新增 `add_claim` 逐条提交、`finalize_answer` 改为无参封卷（消灭最大单次载荷）；运行时对解析失败改为"救援→喂回模型重试"；打通 `MINI_AGENT_MAX_OUTPUT_TOKENS`。目标失败类被**完全消除**。

### 4.5 真实模型端到端可靠性复测（2026-07-10）

隔离专题上传 8 份文本案卷，8/8 加工完成，共 11 个 chunk。矛盾检测第一次暴露 30 条跨时间 AIS 状态误报；加入时间/模态约束和大 JSON 二分重试后，11/11 chunk 完成，得到 103 条接地命题、0 条满足严格条件的矛盾、无 warning。自动研判最终生成 2 个中性开放问题并完成 2/2，均产生候选。

从 supported 问答生成 1 条 Finding 并经 security 核准。报告 revision 1 被测试代码手工修改 markdown 后，提交正确返回 409；重新起草为 revision 2 后完成提交、核准和导出，覆盖率 4/5，隔离数据审计链校验 `ok=true`。简报概览真实模型返回不可解析 JSON，系统显式 `degraded=true`，但自动研判和覆盖率等实时字段仍可见。完整过程见 `docs/report/2026-07-10-real-model-e2e.md`。

### 4.6 工程质量

按 TypeScript 文件统计，全仓约 **32,513 行源码 + 23,132 行测试 + 1,172 行评测脚本**。`pnpm check && pnpm build` 结果为 106 个测试文件通过、1 个跳过，927 个测试通过、3 个跳过，core/server/web 三包构建成功。三个跳过用例均依赖显式外部模型条件。

## 五、创新点

1. **引用台账式的证据级问答**：把"防幻觉"从"提示模型别乱说"变成**结构约束**——`cite` 强制逐字子串 + 内容哈希，答案只能由已接地引用构成，无据即如实说不足。这是可复核而非可信赖的 AI。
2. **结构化矛盾检测**：接地命题抽取 + 实体/属性/模态/时间约束 + 簇内成对判断，产出每条绑定 A/B 引用与 scope 的矛盾。价值定位是可校验 provenance、分批覆盖和审计，不宣称当前 F1 优于直出模型。
3. **过程可审计**：运行轨迹（run trace）× 哈希链审计，使"结论可溯源"升级为"**研判过程本身可回放、可取证**"。
4. **研判过程透明化**：像 Claude Code 一样把工具调用、思考、引用生长实时呈现（事件协议 v2 + 活动流/证据台账），过程与结论同等可追溯。
5. **目标驱动的自动研判**：系统主动出题、逐题取证、候选入池，把人从提问者变为复核者，并以报告覆盖率仪表引导补证——一条清晰的"人机分工"业务闭环。
6. **数据集成治理**：多模态素材、密级、哈希链审计、零外发守卫、报告复核状态机集成为一体，而非只做"AI 分析"。
7. **自研 Agent Runtime 作为基础设施**：确定性 agent 循环、真流式、可恢复 JSONL 会话、运行轨迹、zod 工具、策略沙箱，被产品层深度复用又受领域工具与守卫适配器约束。

## 六、工作情况总结

**工程规模与方法。** 项目在 monorepo 下分三包演进，累计百余次提交。后期集中完成三个阶段的攻坚，全部按"定义可验证目标→测量→修复→复测→提交"推进，并维护变更日志（`implementation-notes.md`）记录每一处偏离：

- **阶段一 · 问答成功率修复**：诊断出 `finalize_answer` 大 JSON 截断这一根因，重设计工具面（`add_claim`/无参封卷）+ 运行时解析自愈，问答错误率 30%→0%，并建立可复现的成功率评测。
- **阶段二 · 研判过程透明化**：SSE 事件协议从 4 种扩展到 11 种，把工具调用、思考、引用台账做成活动流+证据台账双栏，深度模式并入流式通道。
- **阶段三 · 目标驱动工作台**：自动流水线、研判简报、自动研判批处理、报告覆盖率仪表和首轮真模型彩排。
- **全链路可靠性加固**：收紧会话隔离、取消与跨进程一致性，补齐权限吊销、审计、报告版本绑定、分析失败可见性、上传批次和前端持久化状态；并完成 2026-07-10 真实模型复测。

**质量治理。** 除功能外，还完成了一轮文档与自描述的系统化清理：确立单一项目入口、归档过时文档、校正与代码漂移的描述，并把旧 benchmark 明确标记为历史基线。当前矛盾策略的固定标注集复测仍未完成，因此没有提前刷新或包装质量数字。

**收获。** 本项目最大的体会是：**在高可靠性要求下用 LLM，工程重心不在"让模型更强"，而在"让不确定的模型输出可被复核、可追责"。** 引用接地、结构化管线、哈希链审计、密级与零外发，这些机制共同把 AI 从演示品变成了可交付、可讲清楚"结论怎么来的"的研判助手。

## 七、不足与展望（诚实边界）

- **精度非卖点**：历史基线上矛盾检测与大模型直出持平或略低；当前时间/模态策略尚待固定标注集复测，且小规模合成语料不代表真实分布。
- **默认体验依赖配置**：媒体（ASR/OCR/VLM）与稠密 embedding 在未配置真实端点时降级为 mock（无语义），开箱只验证管线打通。
- **实体归一化**：矛盾检测的实体归并目前依赖归一化 + 小型别名表，泛化到真实语料需引入基于嵌入的实体链接。
- **持久化**：扁平文件（无数据库）便于离线部署，但不具备事务与索引，规模化需迁移到 SQLite 等。
- **审计定位**：哈希链是**防篡改取证**，不等同于真实涉密系统的合规认证；密级模型满足课程演示闭环，实战部署需接组织/角色/审批/外部审计锚定。
- **性能**：广度型全案综合问答因增量取证调用变多而偏慢，待做读取批量化与预算策略优化。
- **简报结构化输出**：模型仍可能返回不可解析 JSON；有历史成功快照时可保留 last-good，首次失败时只能显示降级统计。
- **验证覆盖**：2026-07-10 完成了真实模型 API 链路；本机 Browser 插件文件缺失，因此同轮未完成渲染态点击与视觉回归。
- **演示为模拟数据**：演示案卷为虚构，多媒体素材与案情无事实关联，仅用于验证多模态接入与许可溯源。

**展望**：本地嵌入/媒体模型接入以提升默认语义质量；过程持久化回放（运行轨迹已具备 run_id）；技能系统转正为"可插拔研判方法论"；将研判简报与自动研判扩展为跨专题的态势聚合。
