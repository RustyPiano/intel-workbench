## 〇、开场电梯陈述（30 秒，背下来）

> "Intel Workbench 是一个**面向离线/涉密环境的多模态情报证据分析工作台**。素材（文档、图片、音频、视频）进本地工作区后，系统做加工、检索、**交叉验证/矛盾检测**、报告复核与审计留痕，把模型输出**约束在可复核的证据链内**。
>
> 它的底座是通用 RAG——**但通用 RAG 谁都有，不是我们的拿分点**。我们真正自研、能赢'大模型直出'的，是架在底座之上的**垂直情报分析能力：跨源交叉验证与矛盾检测**——一套确定性判定算法，LLM 只是其中一个可替换组件。这一点有 benchmark 量化对比支撑，是我们'非套壳'的硬边界。"

**一句话记忆锚**：底座是 RAG，**拿分点是矛盾检测**；LLM 是组件，**判定算法是我们的**。

## 一、系统架构与数据流

### 分层
- `packages/core`（自研 Agent Runtime，8,401 行 TS）：工具/技能/会话/trace 基础设施，`RuntimeAgent`、`RuntimeTool`。
- `packages/server`（工作台后端，12,512 行 TS）：Express API、鉴权、专题、素材加工、检索、**矛盾检测**、报告、审计、安全。
- `packages/web`（React 工作台，7,230 行 TS/TSX）：登录、专题列表、案卷工作台、审计中心、管理台。

### 端到端数据流
```
素材汇入(ingest) → 加工(OCR/ASR/切块/向量索引) → 存证(chunk + content_hash)
        │
        ├─► 溯源问答  : 受控 agent 检索→逐字引用接地→finalize_answer
        ├─► 要素抽取  : 结构化实体(person/org/location/event/equipment/time)+出处
        ├─► 矛盾检测  : 抽claim→实体聚类→簇内NLI→确定性置信度→带出处冲突
        └─► 报告      : draft→submit→approve(保密员)→export(零捏造闸)
        │
   全程：OfflineGuard 零外发白名单审计  +  哈希链审计日志(可 verify)
```

## 二、核心设计点（逐模块，可翻代码）

### 1. 受控 agentic 溯源问答（今日大改，演示重头）
**是什么**：问答不是"把片段丢给 LLM 让它答"，而是给 LLM 一套**受控工具集**，它自主检索、浏览、引用，但**只能在哈希校验过的证据上接地作答**。
**工具集**（`packages/server/src/inquiry/intel-harness.ts`）：
- 导航：`search_chunks`(混合检索)、`search_materials`(确定性子串)、`list_materials`、`read_material_window`、`expand_chunk`、`read_chunk`——全部受**读取预算**上限约束（`readBudgetBytes`/`perReadCapBytes`，防上下文塞爆）。
- 接地：`cite(chunk_id, claim, quote)`——**双重校验**：① `sha256(chunk.text) === content_hash`（防篡改）② `quote` 必须是原文**逐字子串**（`indexOf(quote) >= 0`），否则拒绝（`intel-harness.ts:396-417`）。返回 `cite_id`。
- 出口：`finalize_answer` 是**唯一出口**，只调一次；**没经过它的内容一律丢弃**（`intel-harness.ts:467-478`）。上限 12 条 claim、每条 8 个引用。
- 结构化候选：`submit_finding` 把已 cite 的引用组织成结构化候选结论（今日新增）。
- 按需多模态：`transcribe`(ASR)/`caption_frame`(VLM)/`ocr_region`(OCR)——**每次出站前先 `guard.authorize()` 审计**（`intel-harness.ts:513/547/574`），产出片段自带 `content_hash`，可继续被 cite 且防篡改。

**为什么这样**：这是"非套壳"的直接体现——答案强制接地、可逐条溯源、防幻觉、防篡改、可审计。演示时点引用能跳回原文/音频时间码。

### 2. 自研矛盾检测 / 交叉验证（皇冠拿分点）
**核心文件**：`packages/server/src/analysis/contradiction-service.ts`（899 行）。**四步流水线**（今日未改动，benchmark 数字对此路径仍成立）：

1. **逐块抽原子 claim**（LLM，思考**关闭**硬编码）：`{entity, attribute, value, chunk_id}`，`extractClaims()` `:694-700`；再经 `groundClaims()` `:702-730` 用 `resolveValidCitations` **丢弃幻造锚点**，只留能对应真实 chunk 的 claim，并绑定 `chunkToCitation`。
2. **按实体确定性聚类（非 LLM）**：`clusterClaims()` `:732-739`，纯 `Map` 分组，key=归一化实体（走案内 `elements.json` 别名表）。**聚类零 LLM 参与**。
3. **仅簇内成对 NLI**：`judgeClusters()` `:741-760`，`enumeratePairs()` 只在同簇内做 C(n,2)，复杂度 **O(Σnᵢ²) 而非 O(N²)**。先过**确定性规则短路** `cheapJudgePair()`（同值→一致、反义词→矛盾），未命中才落 LLM NLI，判 `contradiction|agreement|unrelated`+`certainty`。
4. **确定性置信度 + scope**：`confidence = certainty*0.5 + (跨源?0.3:0) + 数值距离奖励`（`:790-792`）；`scope` 按 `material_id` 是否相同分 `cross/intra-material`。两端 claim 各绑 `content_hash`，**逐条 provenance**。

**规模化**：`detectFromChunks()` 对**全案全部 chunk** 按 40 块/批切批、并发 4 跑，结果**确定性拼接合并**（非 LLM 合并）——语料再大也不会一次调用丢上下文。

**一句话点睛**（背下来）：
> "让 LLM 找矛盾"会漏、会飘、无出处；我们是**先结构化抽取带出处的原子主张，再用确定性算法聚类、只在同实体簇内成对判定，最后给确定性置信度**。**LLM 只负责单点的语义判定，判定框架是我们的**——这就是非套壳的硬边界。

### 3. 混合检索栈
`packages/server/src/inquiry/retrieval.ts`。**BM25 ⊕ dense 向量 → RRF 融合 → Reranker 重排**：
- BM25：`retrieve()` `:32-62`（K1=1.5, B=0.75），中文 CJK 二元+一元 grams 分词。
- Dense：cosine + `denseSearch()`；无向量时**自动退化纯 BM25**（`:189-191`）。
- 融合：标准 **RRF**（k=60，`rrf()` `:163-172`）。
- 重排：第二阶段 `rerankTopK()`，过取深度 24 → 取 top-k。
- 增强项（Contextual Retrieval / query-rewrite / HyDE）**全部默认关**（`rag-config.ts`）；且 query-rewrite/HyDE **只在 legacy 单轮模式**触发，默认 agent 问答路径**根本不走**——benchmark 证明它们在干净语料上不增益甚至降分，故做成 opt-in，**由数据定默认**。

### 4. OfflineGuard 零外发红线
`packages/server/src/security/offline-guard.ts`。**应用层协作式闸门**（非网络层 hook）：每个出站点显式调 `authorize(url, {user, purpose})`——① 先**无条件写审计**（`egress.allow`/`egress.deny`）② 未在白名单则抛 403。白名单=**已配置的 LLM + 媒体 slot 端点 host**（`app.ts:129-132`），未配置即拒绝。有真实测试断言"空白名单→403 + `egress.deny` 审计"。

### 5. 审计哈希链
`packages/server/src/audit/audit-service.ts`。`event_hash = sha256(payload_hash + prev_hash)`，创世哈希全 0；`verify()` 逐条重算比对，任一不符返回 `brokenAt`。有**真实篡改测试**（改落盘记录 user 字段→verify 检出 `ok:false`）。写入时机="**先落业务产物，再 append 审计**"（多处调用点核实）。**今日未改动**，可放心讲。

### 6. 密级 RBAC + 会话安全
- 角色 `operator|admin|security`；密级 `internal<secret<confidential<topsecret`（`domain/types.ts`）。
- 专题**按密级服务端裁剪**；写操作限 **owner 或 admin**；审核类操作（矛盾确认/finding 复核/报告批准）限 **security 或 admin**。
- 登录：本地静态用户库 + `scryptSync`，**防用户名枚举**（不存在用户也跑等价假哈希抹平耗时）；会话 token=`randomBytes(32)` 存内存，TTL 12h；**5 次失败锁 5 分钟**。
- 默认不建演示账号；仅 `MINI_AGENT_DEMO=1` 种 `admin/operator/security` 固定口令。生产首启生成一次性随机 admin 口令并强制改密。

### 7. 多模态媒体管线
- 切块：段落贪心拼接（目标 600 字、上限 1200，`material-service.ts`）。
- OCR：PaddleOCR HTTP；ASR：FunASR HTTP（**句级时间戳 + 说话人**，cam++ 分离在外部服务）；视频分镜：ffmpeg `scene>0.3` 阈值（非 TransNetV2，部署期增强）。
- **降级而非崩溃**：服务没起/没 key → 该能力静默降级并记 note；`MINI_AGENT_USE_MOCK_MEDIA=true` 出确定性假数据兜底。

### 8. 报告零捏造导出闸
`packages/server/src/report/report-service.ts`。状态机 `draft→submit→approve(限保密员/admin)→export`。**导出闸** `evaluateExportGate()`：逐条校验引用完整性（`content_hash` + span `quote_hash` + 原文切片比对）、正文覆盖度、高严重度矛盾是否处理；任一不过抛 409 且逐条落 `report.export.gate` deny 审计。**豁免字段**：标题/密级标识/收发文/日期属行政字段，不要求引用（**有意为之、已文档化**）。

### 9. 智能建议层（今日新增，慎讲）
`context/`、`prompt/`、`suggestion/` 模块 + 端点 `suggestions/questions-llm`、`suggestions/findings`、`report/auto-draft`。**刚落地、有测试但未上 benchmark/未端到端人工验证**——见第六节风险，讲这块用"刚做完、测试过但没上 benchmark"的措辞，别用旧文档数字背书。

## 五、Benchmark 量化对比（⚠️ 数字需复现确认）

> 复现：`source dev.env.sh && npm run eval:contradiction`（矛盾）/ `npm run eval[ --variant=...]`（检索）。
> **诚实声明**：下列数字来自 `docs/report/benchmark-summary.md`（定格 6/23）。核心算法今日**未改动**，数字对**默认路径**大概率仍成立；但今晚前若来得及，**建议重跑一次**，答辩时说"最近一次评测结果为…"。

### 矛盾检测（自造语料：≈30 切块/6 文件/12 金标矛盾对）
| 方案 | Precision | Recall | F1 |
|---|---:|---:|---:|
| **anchored（关思考，默认）** | 1.000 | 0.917 | **0.957** |
| anchored（开思考） | 1.000 | 0.833 | 0.909 |
| llm-direct（全块丢 LLM） | 1.000 | 0.917 | 0.957 |

**关键话术（务必诚实，别吹精度）**：
> "我们的 F1 **追平**直出（0.957 = 0.957），**不是精度碾压**。但直出给不了这四样：**每条矛盾绑定可校验的逐条 provenance（零捏造引用）、全语料分批覆盖、确定性可复现、全程可审计**。这才是结构化算法相对'一次性丢给大模型'的真实价值。"
>
> "而且我们做了 thinking on/off **对照实验**：本以为 NLI 该开思考，实测**开思考 recall 反而从 0.917 掉到 0.833**——推理模型'想多了'把真矛盾判成无关。于是**用 benchmark 数据把默认设成关思考**。这就是老师要的'建机制→跑对照→数据定默认'的闭环。"

### 检索质量（合成语料 45 文档/227 切块/100 标注 query）
- 强 hybrid+rerank **基线已饱和**：R@10=0.950，rerank nDCG@10=0.924。
- 通用 RAG 增强**总体不增益**（Contextual Retrieval 仅在重排阶段微增到 nDCG 0.930；query-rewrite/HyDE 在贴合 gold 的 query 上过度发散反而降分）。**这是诚实负结果**：界定了技术适用边界（脏/欠定语料才有用），并把创新拿分点上移到矛盾检测。

### 证据级/任务级（确定性夹具）
引用定位准确率 3/6、报告引用覆盖率 3/5、**失败可见率 4/4=1.000**（篡改/失败批/越权/空向量均显式暴露）、**重复运行一致性 = true**（同输入两跑 sha256 相等）。

## 七、预判提问 & 标准答案（防被问住）

**Q：这跟直接问 GPT/DeepSeek 有什么区别？**
A：三点。① 答案**强制接地**——每条结论绑定哈希校验过的逐字原文引用，未接地内容直接丢弃，防幻觉。② 矛盾检测是**确定性算法框架**，LLM 只做单点语义判定，可复现、有出处、能覆盖全语料。③ 全程**离线零外发 + 哈希链审计**，涉密可用。GPT 直出这三样都给不了。

**Q：矛盾检测比大模型直出强在哪？F1 更高吗？**
A：**诚实说——F1 是打平的（0.957=0.957）**，我们不吹精度。强项是**零捏造的逐条 provenance、全语料分批覆盖、确定性可复现、可审计**。而且我们靠 benchmark 发现"NLI 开思考反降召回"，用数据把默认定成关思考——这是设计闭环，不是拍脑袋。

**Q：为什么有些检索增强默认关？是没做完吗？**
A：不是，都实现了。是 benchmark 证明它们在**干净语料上不增益甚至降分**，价值在脏/欠定语料。所以做成 opt-in、默认关，**由数据决定**——这本身是规范性的体现。

**Q：离线/零外发怎么保证？**
A：OfflineGuard 应用层白名单闸门，每个出站点先 `authorize` 再放行，白名单只含已配置的本地端点 host，未放行一律 403 且**先落审计**。补一句诚实边界见下。

**Q（尖锐）：零外发是网络层强制的吗？密级隔离滴水不漏吗？**
A：**主动交代两点**——① OfflineGuard 是**应用层协作式闸门**，覆盖所有应用出站调用点并审计，但不承诺拦 OS/第三方库的越界出网（代码注释写明），气隙部署时靠物理断网兜底。② 开发模式（`devMode`）**只禁止"创建"新涉密专题，不禁止已具高密级身份用户"进入"已存在涉密专题**——这与工程方案 §7.5 表述有出入，是**设计口径差异**，已知、可补齐。主动说这两点比被问出来强。

**Q：审计日志能被篡改吗？**
A：哈希链，`event_hash=sha256(payload_hash+prev_hash)`，改任一条都会断链，`verify()` 能定位 `brokenAt`。有真实篡改测试覆盖。

**Q：工作量多大？**
A：约 28,000 行 TS，101 测试文件 783 用例，自研 Agent Runtime + 24 个后端服务 + 多模态管线 + 完整前端，当前测试全绿。

**Q：这些是你自己写的还是套的开源？**
A：Agent Runtime、检索栈、矛盾检测算法、审计哈希链、导出闸都是自研；LLM/Embedding/OCR/ASR 是**可替换的外部模型服务**（OpenAI 兼容口），我们的价值是**判定算法与证据链框架**，模型是组件。
